# MOOtation

*[English](README.md) · **Русский***

[![DOI](https://zenodo.org/badge/1328202748.svg)](https://doi.org/10.5281/zenodo.21864324)
[![License](https://img.shields.io/badge/license-Apache--2.0-blue.svg)](LICENSE)

**63 алгоритма многокритериальной и многомерной (many-objective) оптимизации
(62 эволюционных и один прямого поиска), каждый реализован по своей статье и
сверен с ней построчно.
Header-only C++17 без зависимостей; доступен также из Python, из TOML-файла,
который управляет внешним солвером, и из любого языка с C FFI.**

Библиотека существует ради одного: когда в статье сравниваются с NSGA-III или
MOEA/D-DE, нужен алгоритм, который опубликовали авторы, а не чьё-то прочтение.
Каждый заголовок здесь называет статью, прослеживает одно поколение в
обозначениях самой статьи, приводит её параметры по умолчанию с указанием
раздела и объявляет под номером каждое отклонение и каждое разрешение
неоднозначности в тексте. Название: *MOO* (multi-objective optimization) плюс
*mutation*, оператор, на котором стоят все эти алгоритмы.

## Что вы получаете

- **63 алгоритма** в восьми семействах: доминирование Парето, опорные точки в
  стиле NSGA-III, семейство MOEA/D, индикаторные, на опорных векторах,
  кластерные, архивные и прямой поиск. Полный список с DOI и подсказки по выбору:
  [docs/algorithms.md](docs/algorithms.md).
- **Бумажный след в каждом файле.** Параметры статьи, объявленные отклонения,
  разрешённые неоднозначности и место, где подключена обработка ограничений,
  всё в заголовке того алгоритма, который этим пользуется.
- **Пять входов, один список алгоритмов.** Шаблон C++, сессия ask/tell в C++,
  Python `minimize`, TOML-описание запуска для внешних программ и C ABI. Все
  пять порождаются из одного `algorithms.def`, поэтому не расходятся.
- **436 тестовых задач** (ZDT, DTLZ, WFG, MaF, ZCAT, bbob-biobj, MOP, BT,
  многоугольники Ишибучи) с истинными фронтами Парето там, где есть замкнутая форма,
  IGD / IGD+ / гиперобъём и раннер кампаний, который режет работу на шарды для
  кластера.
- **Тёплый старт**, журнал вычислений, обработка ограничений в каждом
  алгоритме (по умолчанию выключена, как в статьях) и `--check`, который
  отвергает запуск через десять секунд, а не через десять минут суточного
  расчёта.

## Чего здесь нет

- Это не конструктор из взаимозаменяемых блоков отбора и вариации. Каждый
  алгоритм написан так, как его излагает статья; связка между шагами обычно и
  есть вклад статьи.
- Это не воспроизведение экспериментальных таблиц статей. Верность
  проверялась по тексту; тесты проверяют сходимость на DTLZ2, а не повторяют
  бенчмарки.
- Только вещественный и бинарный геномы (46 алгоритмов принимают бинарный
  или смешанный геном, 16 от него отказываются). Нет родных целочисленного,
  категориального и перестановочного типов и порядковых операторов;
  перестановки идут через random keys.
- Нет специализированных алгоритмов для задач с ограничениями, с суррогатами,
  динамических, зашумлённых и крупномасштабных. Обработка ограничений
  приделана поверх безусловных методов, и каждый заголовок об этом говорит.
- Из Python и через C ABI геном только вещественный.

## Установка

**C++.** Скопируйте `include/` или подключите через CMake; библиотека
header-only, ей нужен компилятор C++17 и ничего больше.

```cmake
add_subdirectory(MOOtation)                       # или FetchContent, или find_package(MOOtation)
target_link_libraries(app PRIVATE MOOtation::MOOtation)
```

**Python.** На машине нужны компилятор C++ и CMake; колесо собирается при
установке.

```bash
pip install .            # оптимизатор
pip install ".[all]"     # плюс наборы задач (NumPy) и терминальный интерфейс (Textual)
```

**C ABI.** Одна разделяемая библиотека, `libmootation.so` / `libmootation.dylib` /
`mootation.dll`, цель `MOOtation::c`.

```bash
cmake -S . -B build -DMOOTATION_BUILD_C_API=ON && cmake --build build
```

владеет циклом и что пересекает границу, а не в том, что можно запустить.

## Быстрый старт

**C++, один алгоритм.** `examples/nsga2_zdt1.cpp`:

```cpp
#include <mootation/mootation.hpp>
#include <iostream>

int main() {
    using namespace mootation;

    Problem<NSGAII_Individual>   prob;               // задача по умолчанию: ZDT1, n = 6
    DataVault<NSGAII_Individual> vault(100, prob);   // размер популяции 100

    // defer_setup сохраняет воспроизводимость: конструктор с одним аргументом
    // разыграл бы начальную популяцию до того, как set_seed() успел бы что-то изменить.
    Optimizer<NSGAII_Individual, NSGAIICore<NSGAII_Individual>>
        opt(std::move(vault), defer_setup);
    opt.get_algorithm().set_seed(12345);
    opt.setup();
    opt.optimize(500);                               // 500 поколений

    auto& v = opt.get_vault();
    for (std::size_t i = 0; i < v.active_n(); ++i)
        std::cout << v.objectives_of(i)[0] << ' ' << v.objectives_of(i)[1] << '\n';
}
```

```bash
g++ -std=c++17 -O2 -Iinclude examples/nsga2_zdt1.cpp -o nsga2_zdt1 && ./nsga2_zdt1
```

**C++, цикл ваш.** Алгоритм выбирается по имени из структуры настроек или
файла `ключ = значение`; `ask()` выдаёт кандидатов, `tell()` принимает их
целевые значения и возвращает следующих. Размер пакета выбирает алгоритм, а не
`pop_size`: поколенческие алгоритмы отдают всё потомство разом, стационарные
по одному кандидату.

```cpp
#include <mootation/embed.hpp>

mootation::Session s(mootation::Settings::from_file("run.cfg"));

std::vector<std::vector<double>> F;
for (auto X = s.ask(); !X.empty(); X = s.tell(F)) {
    F.assign(X.size(), std::vector<double>(s.n_objs()));
    for (std::size_t i = 0; i < X.size(); ++i)
        F[i] = my_simulator(X[i]);                   // на входе переменные одного кандидата
}
mootation::Result r = s.result();
```

`examples/run.cfg` документирует каждый ключ файла настроек. Подробности,
однострочный `run()`, тёплый старт и цена компиляции рантайм-диспетчеризации:
[docs/embedding.md](docs/embedding.md).

**Python.**

```python
import mootation

def zdt1(x):
    g = 1 + 9 * sum(x[1:]) / (len(x) - 1)
    return [x[0], g * (1 - (x[0] / g) ** 0.5)]

res = mootation.minimize(zdt1, bounds=[(0, 1)] * 10, n_objs=2,
                         algorithm="nsga2", pop_size=100, n_gen=250)
print(res.objectives[0], res.ignored)
```

Ограничения задаются второй функцией, возвращающей нарушения (`<= 0` значит
выполнено); `batch=` получает всё поколение одним вызовом, для дорогих
вычислителей; `save_population=` / `seed_population=` это тёплый старт;
`mootation.algorithms()` перечисляет 63 имени. `res.ignored` называет каждую
ручку, которой у выбранного алгоритма нет. Шесть разобранных скриптов лежат в
[python/examples/](python/examples/README.md); `mootation.Problem` /
`mootation.Config` / `mootation.run_raw` повторяют C++ API один к одному, когда
`minimize` мало.

**Внешние программы, из TOML-файла.**

```bash
python -m mootation.run --show --check python/examples/demo.toml   # сначала проверить
python -m mootation.run python/examples/demo.toml                  # затем запустить
```

Файл называет шаги (массивы argv, переопределения под платформу), как
разбирать их вывод (CSV, JSON, регулярное выражение, столбцы или функция на
Python), что делать при неудачном вычислении и куда писать журнал. `--check`
проверяет исполняемые файлы, шаблоны, границы, имена алгоритмов и ограничения
на размер популяции до того, как начнётся что-то дорогое.
[docs/running.md](docs/running.md).

**C и всё, у чего есть FFI.**

```c
#include <mootation/capi.h>
#include <stdlib.h>

moo_session* s = moo_open("algorithm = nsga2\n"
                          "pop_size  = 40\n"
                          "max_gen   = 40\n"
                          "n_vars    = 10\n"
                          "n_objs    = 2\n"
                          "lower     = 0\n"
                          "upper     = 1\n");
int nv = moo_n_vars(s), no = moo_n_objs(s);

for (int n = moo_ask_count(s); n > 0; ) {
    double* x = malloc((size_t)n * nv * sizeof(double));
    double* f = malloc((size_t)n * no * sizeof(double));
    moo_ask(s, x, n * nv);                     /* n строк по nv переменных */
    for (int i = 0; i < n; ++i)
        my_simulator(&x[i * nv], &f[i * no]);
    n = moo_tell(s, f, n * no, NULL, 0);       /* возвращает СЛЕДУЮЩИЙ размер */
    free(x); free(f);
}
int m = moo_result_count(s);                   /* итоговая популяция */
moo_close(s);
```

Через границу проходят только типы C: конфигурация уходит одной строкой в
формате настроек, кандидаты и целевые значения ходят плоскими row-major
массивами `double`, каждый неудачный вызов возвращает отрицательное число или
`NULL` и оставляет сообщение в `moo_last_error()`. `capi/ctypes_demo.py`
крутит тот же цикл из Python одним `ctypes`; в `capi/wrappers/` лежат
адаптеры для Julia, R и MATLAB, которые ещё никто не запускал.
[docs/embedding.md](docs/embedding.md#the-c-abi).

## Как выбрать алгоритм

| семейство | сколько | когда брать |
|---|---|---|
| доминирование Парето и разнообразие (NSGA-II, SPEA2, ...) | 8 | два-три критерия, базовая линия, которую все узнают |
| опорные точки, семейство NSGA-III | 4 | много критериев, регулярный фронт; `pop_size` должен быть размером решётки Даса–Денниса |
| декомпозиция, семейство MOEA/D | 16 | скаляризуемые задачи, много критериев, дешёвые поколения |
| индикаторные (IBEA, HypE, R2, ...) | 13 | важен один индикатор качества; стоимость растёт с числом критериев |
| опорные векторы и углы (RVEA, ...) | 8 | нерегулярные или плохо масштабированные фронты |
| кластерные | 11 | разрывные или нерегулярные фронты |
| архивные | 2 | ответ это история недоминируемых, а не фиксированная популяция |
| прямой поиск (DMS) | 1 | мало переменных, детерминированный ответ |

Если ваши цели различаются на порядки, начните с
[docs/algorithms.md](docs/algorithms.md#if-your-objectives-are-not-commensurate):
равномерное перемасштабирование проверяется на каждом пуше и ничего не меняет,
а соотношение между осями выдерживают своими силами лишь 18 алгоритмов.

Семнадцати алгоритмам нужен `pop_size`, равный точному размеру решётки для
данного числа критериев, семейству M2M нужен размер, кратный числу
подобластей; `python -m mootation.run --check` называет ограничение и ближайшие
допустимые размеры, а каждое ядро сообщает о ручках, которых у него нет,
вместо того чтобы молча их отбросить. Таблицы со всеми алгоритмами, годом,
файлом и DOI: [docs/algorithms.md](docs/algorithms.md).

## Верность источнику

Каждый алгоритм сверялся с первоисточником в три прохода: двойной слепой
построчный аудит с арбитражем, адверсариальный проход с опровержением каждой
находки и заключительный проход с чек-листом на алгоритм, где каждое
уравнение, каждая строка псевдокода и каждый параметр полной статьи сопоставлены
с местом в коде. Где статья говорит явно, код ей следует; где статья молчит,
неоднозначна или противоречит себе, заголовок цитирует фрагменты и говорит,
какое чтение взято и почему. Где буквальное чтение измеримо ломает метод,
заголовок приводит измерение и переключатель, включающий букву. Каждый файл
переносит свою статью.

Код чист от предупреждений при `/W4 /WX` и `-Wall -Wextra -Werror` и чист под
ASan / UBSan на всех алгоритмах; и то и другое проверяет CI. Чего всё это не
даёт: воспроизведения опубликованных результатов статей. Набор тестов
проверяет, что каждый алгоритм сходится на DTLZ2 в грубом допуске и что
обработка ограничений живая, не более. Отчёты о верификации обильно цитируют
статьи и потому хранятся вне репозитория; выводы живут в заголовках.

## Бенчмарки и кампании

В `mootation.benchmarks` 436 задач из 15 семейств, от 2 до 15 критериев, у
каждой границы, вычислитель, опорная точка для гиперобъёма и, где есть
замкнутая форма, выборка истинного фронта Парето. `mootation.run.metrics`
считает IGD, IGD+ и гиперобъём (точно до пяти критериев, Монте-Карло выше).
Секция `[campaign]` в файле запуска превращает произведение семейство × число
критериев × алгоритм × сид в возобновляемые задания с траекторией сходимости
у каждого, локально или как массив SLURM:
[docs/running.md](docs/running.md#campaigns). Потом `--ranks igd` или `t` на
вкладке Compare в TUI сводит результаты в одну строку на алгоритм: средний ранг
в целом, по семействам и по числу критериев.
[`python/examples/campaign_all.toml`](python/examples/campaign_all.toml) ставит
все 58 алгоритмов на 53 задачи, а в
[docs/running.md](docs/running.md#all-58-algorithms-on-another-machine) есть
рецепт, как прогнать его на другой машине или разложить на несколько.

## План развития

В порядке того, сколько трения снимает каждый пункт.

- Настоящая контрольная точка. Тёплый старт работает везде; положение ГПСЧ и
  внутреннее состояние каждого алгоритма пока не сериализуются, поэтому
  возобновлённый расчёт стартует с той же популяции, но не по той же
  траектории.
- Встроенный параллельный вычислитель: `batch_executor` это крюк, `n_workers`
  должен стать параметром.
- Сигнатуры Python на NumPy и бинарные геномы в Python-биндинге и C ABI.
- Родные операторы перестановок и целых чисел.
- GD+ и модуль метрик на C++ (гиперобъём есть только внутри трёх алгоритмов и
  в Python); тест Уилкоксона в сравнении кампаний.
- Точный отбор подмножества по гиперобъёму при двух критериях: он стоит
  `O((n-k)k + n log n)`, а жадное удаление, предписанное статьями, при двух
  критериях слабейшая из трёх жадных схем. Это будет заявленным отклонением,
  а не исправлением, поэтому нужен переключатель с замером.
- Точные эталонные фронты для частично вырожденных задач (DTLZ5, DTLZ6, MaF6
  от 4 критериев, WFG3 уже от 3): либо опубликованная характеризация
  невырожденной части, либо ограничения, делающие их по-настоящему
  вырожденными. Выборка с фильтром не годится: она возвращает точки,
  непобеждённые лишь внутри выборки. Сегодня об ограничении предупреждает код.
- Запуск обёрток Julia, R и MATLAB на машине, где они есть.

## Участие, цитирование, лицензия

У вклада одно правило: реализация должна соответствовать статье, на которую
претендует. См. [CONTRIBUTING.md](CONTRIBUTING.md) и
[docs/writing-an-algorithm.md](docs/writing-an-algorithm.md) с контрактом Core
и соглашением о заголовке.

Каждый релиз архивируется на Zenodo; цитируйте концептуальный DOI, который
всегда ведёт на новейший релиз, и цитируйте статью каждого алгоритма, которым
пользуетесь, ведь метод взят оттуда.

